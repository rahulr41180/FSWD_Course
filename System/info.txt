
Yes, they are **different concepts**, but they are closely related and often used together when designing software systems.

Think of it like building a city:

```text
System Design       = Planning the entire city
System Architecture = Designing the city's structure and zones
System Patterns     = Reusable city layouts and blueprints
System Flow         = How people, vehicles, and services move through the city
```

---

# 1. System Design

System Design is the broadest topic.

It focuses on:

* What to build
* How components interact
* Scalability
* Reliability
* Performance
* Security
* Availability

Examples:

* Design WhatsApp
* Design YouTube
* Design Uber
* Design Google Drive

---

# 2. System Architecture

System Architecture is a subset of System Design.

It defines:

```text
Services
Databases
Queues
Caches
Communication
Deployment
Infrastructure
```

Example:

```text
Client
   |
API Gateway
   |
--------------------
|        |         |
Auth   User    Payment
Service Service Service
```

Architecture answers:

```text
What components exist?
How do they communicate?
```

---

# 3. System Patterns

Patterns are reusable solutions.

Example:

Instead of reinventing the wheel:

```text
Microservices Pattern
Event Driven Pattern
CQRS Pattern
Saga Pattern
MVC Pattern
```

These are architectural patterns.

# 4. System Flow

System Flow explains:

```text
Request flow
Data flow
Control flow
Event flow
```

Example:

```text
User Login

Browser
  |
API
  |
Auth Service
  |
Redis
  |
Database
```

This is a flow.

# 2. Low-Level Design (LLD)

LLD focuses on:

```text id="nqkhrj"
Class Design
Object Design
Methods
Interfaces
Relationships
Design Patterns
```

Questions LLD answers:

```text id="x3bsvr"

What methods?
What properties?
Inheritance?
Composition?
```

Example:

```java id="m52mly"

    private String name;
    private String email;
}

class Order {
    private User user;
    private List<Product> products;
}
```

This is LLD.
