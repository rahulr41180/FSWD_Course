# 1. What is `var`?

`var` is a keyword used to declare variables in JavaScript.

```javascript

```

Here,

```
var -> keyword
name -> variable
Rahul -> value
```

Variables store data.

```javascript

```

Instead of writing


everywhere, we store it.

# 17. var with Closure

Classic interview question.

```javascript
function outer(){

    var count = 0;

    function inner(){

        count++;

        console.log(count);

    }

    return inner;

}

const fn = outer();

fn();

fn();

fn();
```

Output

```
1

2

3
```

Reason

The inner function closes over `count`, so it retains access to the same variable even after `outer` has finished executing.

# 18. var with setTimeout (Famous Interview Question)

```javascript
for(var i=1;i<=5;i++){

    setTimeout(function(){

        console.log(i);

    },1000);

}
```

Output

```
6
6
6
6
6
```

Why?

All callbacks share the same `i`. By the time they execute, the loop has completed and `i` equals `6`.

**Fix using `let`:**

```javascript
for(let i=1;i<=5;i++){

    setTimeout(function(){

        console.log(i);

    },1000);

}
```

Output

```
1
2
3
4
5
```

**Fix using `var` with an IIFE:**

```javascript
for (var i = 1; i <= 5; i++) {
    (function(current) {
        setTimeout(function() {
            console.log(current);
        }, 1000);
    })(i);
}
```

Output

```
1
2
3
4
5
```

The IIFE creates a new function scope for each iteration, capturing the current value.

# Best Practices

Although `var` is still valid JavaScript, modern code generally prefers `let` and `const`.

* Use `const` by default.
* Use `let` when a value needs to change.
* Avoid `var` in new projects because its function scope and hoisting can lead to subtle bugs.

# Before We Start

Many beginners think JavaScript executes code like this:

```
Line 1
↓

Line 2
↓

Line 3
↓

Line 4
```

❌ That's NOT true.

JavaScript actually executes every program in **two phases**.

```
          JavaScript Code

                 │
                 ▼

        Phase 1 : Creation Phase
                 │
                 ▼

        Phase 2 : Execution Phase
```

These two phases happen **every time an Execution Context is created**.

For example:

* Global Execution Context
* Function Execution Context

Both have these two phases.

# What is an Execution Context?

Think of it as a **workspace** where JavaScript executes code.

Whenever JavaScript starts running,

it creates

```
Global Execution Context
```

Inside that execution context,

JavaScript performs

```
1. Creation Phase

2. Execution Phase
```

# Why Do We Say "`var` is Hoisted"?

People say

```
var is moved to the top.
```

This is **not literally true**.

The JavaScript engine **does not rewrite your code**.

Instead, during the **Creation Phase**, it creates memory for all `var` declarations before executing any line.

So this:

```javascript
console.log(age);

var age = 25;
```

behaves **as if** it were:

```javascript
var age;

console.log(age);

age = 25;
```

This "as if" behavior is what we call **hoisting**.

# Key Points to Remember

| Creation Phase                     | Execution Phase                       |
| ---------------------------------- | ------------------------------------- |
| Happens first                      | Happens second                        |
| Scans the entire scope             | Executes line by line                 |
| Creates memory for `var` variables | Assigns actual values                 |
| Initializes `var` with `undefined` | Runs assignments and other statements |
| Does **not** execute `= value`     | Executes `= value`                    |
| No `console.log()` calls run       | `console.log()` statements execute    |

---

# Golden Rule (Memorize This)

Whenever JavaScript enters an execution context:

1. **Creation Phase**

   * Scan the entire scope.
   * Create memory for all `var` variables.
   * Initialize each `var` to `undefined`.
   * Register function declarations (their full function objects are available immediately).

2. **Execution Phase**

   * Execute the code from top to bottom.
   * Perform assignments.
   * Evaluate expressions.
   * Call functions.
   * Update values in memory.

Understanding these two phases is the foundation for mastering **hoisting**, **function execution contexts**, **`let`/`const` and the Temporal Dead Zone**, **closures**, and the **JavaScript execution model**.
